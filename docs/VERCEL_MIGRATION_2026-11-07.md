## Scope and boundaries

Move web delivery only. Keep the two existing Firestore projects, immutable
receipts/revisions, public browser rules, publication tooling, signing and Base
attestations in their existing environments. No database copy or blockchain
transaction is part of this migration. Retain Firebase frontends during the
observation and rollback window.

## Source and release route

GitHub CI remains required before candidate release. Its tests cover receipt
digests, schemas, EAS encoding, tamper detection, permanent routes and identity
separation. Build without Firestore reads; public page and receipt ISR is
generated on demand with a five-minute revalidation interval. The sitemap
continues to read bounded catalogs at request time.

The existing Vercel GitHub installation has selected-repository access and does
not include this public repository. GitHub requires an organization owner to
change that selection. The old local Vercel CLI credential is expired; do not
start a login flow without the owner.

Until native Git integration is connected, use the authenticated Vercel
connector and source-file deployments generated by
scripts/operations/vercel-source-files.mjs EXACT_REVIEWED_SHA. The bootstrap
fetches only TheFutureEdge/open-forecast-receipt at that exact public commit,
verifies FETCH_HEAD, then checks out and installs the committed lockfile.
Record the exact commit in deployment metadata and retain build-log proof.
Local .env files and credentials are never uploaded.

The user's migration authorization covers focused commits, pushes, release
branches, CI, candidate deployments and the scoped infrastructure above.
Do not issue new attestations or publish new forecast data for a hosting test.

## Publication verification

Production smoke verification defaults to https://forecastlibrary.com. Staging
defaults to https://forecast-library-staging.vercel.app. Use
--base-url=EXACT_ENVIRONMENT_ORIGIN or OFL_LIBRARY_BASE_URL for the retained
Firebase staging origin. Protected staging verification accepts the owned
OFL_AUTOMATION_BYPASS_SECRET in memory; never print or commit its value.

## DNS handoff and rollback

Both apex and www are attached and ownership-verified on the production
Vercel project. Public DNS still serves Firebase at 35.219.200.13; TTL is 3600.
Vercel's project-specific recommendation is A 216.150.1.1 and A 216.150.16.1.
Before changing DNS, verify the final deployment and domain recommendations
again. Preserve NS, MX, TXT, certificate, DNSSEC and all other unrelated records.
The www host already has a Firebase claim TXT, so retain A records there rather
than replacing them with an incompatible CNAME.

After candidate acceptance, change only the serving A records for @ and www
to the verified Vercel values and check authoritative plus recursive DNS,
trusted HTTPS, canonical/redirect behavior, public receipts and browser reads.
To roll back the initial cutover, restore both names to A 35.219.200.13 and
verify the retained Firebase service. DNS rollback has resolver delay.

Allow 24-48 hours of observation before a separately reviewed retirement of
the old frontends. Confirm there are no publication callbacks, tagged serving
revisions or automatic rollouts that depend on them before disabling them.
Keep Firestore, backups and the public receipt identity contract intact.
